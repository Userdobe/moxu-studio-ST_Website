# 后台监控闭环设计

## 意图

在现有登录、用户首页、项目与模型配置能力之上，补齐管理员对用户注册、新增项目、积分消耗、模型调用和模型配置更新的只读监控。

## 目标

- 统计所选时间范围内的新注册用户和新增项目。
- 记录并展示模型配置新增、更新、清除事件。
- 区分模型调用事件与积分消耗，保留现有实时 SSE 更新能力。
- 继续使用管理员邮箱白名单和现有登录会话，不暴露 API Key，不增加管理写操作。

## 非目标

- 不新增数据库或第三方分析服务。
- 不在后台修改用户、积分、项目或模型配置。
- 不重做现有用户首页和登录流程。

## 方案

复用 `store.transactions` 作为轻量事件账本：新增用户、项目和模型更新写入不影响余额的事件记录；模型调用继续使用已有 usage 交易。`getUsageSnapshot` 聚合 totals、趋势和最近事件，`AdminDashboard` 增加统计卡片、事件类型展示和用户/项目/模型摘要。这样最少改动即可覆盖现有 JSON 持久化和管理员只读权限。

## 约束

- 统计窗口继续支持 1h、24h、7d、30d。
- 事件中只返回公开字段和模型名称，不返回密钥。
- 兼容旧数据：缺少新字段时按 0 或空数组处理。
- 以小型 Node 自检脚本验证聚合逻辑，再运行 lint/build。
