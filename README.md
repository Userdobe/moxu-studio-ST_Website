# 墨序 Studio｜漫剧创作产品技术手册

墨序 Studio 是一个面向漫剧、短剧创作者的 Web 创作工作台，帮助用户从一句灵感或一段剧本开始，整理创作规范、调用大模型拆解场景，并在项目中持续保存和管理创作内容。

本文介绍产品背景、当前实现的功能、技术栈、本地启动方式、测试入口和部署配置。功能状态以当前代码为准。

## 产品背景

漫剧制作通常需要在灵感记录、剧本整理、场景拆分、分镜编排和项目管理等环节之间反复切换。墨序 Studio 将这些创作入口集中在同一工作台中，并通过账号保存个人配置和项目进度。

产品采用深色、低干扰的创作界面，以左侧导航切换首页、无限画布、短剧工坊、SKILL、角色设定、成片管理和个人设置。前端应用与 API 后端可分别部署；另提供受管理员邮箱白名单保护的只读网页监控后台。

## 产品功能

### 创作首页

- 提供“灵感来自一句话”输入和开启短剧创作入口。
- 展示图片、视频灵感示例和最近项目入口。
- 首页作品展示为示例内容，不代表网站已接入图片或视频生成服务。

### 无限画布

- 创建、打开和删除独立画布项目。
- 在画布上组织场景节点，支持拖动、缩放、平移和自动布局。
- 编辑场景内容并自动保存到当前账号。
- 支持导出项目 JSON 文件。

### 短剧工坊

- 创建独立短剧项目，编辑剧本内容并自动保存。
- 支持导入 `.txt`、`.md`、`.markdown` 和 `.docx` 文档；单文件最大 10 MB，文本长度上限 50 万字符。
- 点击“推理分镜”后，系统将所选 Skill 和个人提示词模板作为模型创作指令、将剧本作为独立素材发送给聊天大模型，生成可用于视频模型的逐镜视频提示词。结果展示在独立分镜界面；模板中的自定义字段、角色表和道具表会保存并展示。模型回复支持从 Markdown 围栏或附加说明中提取 JSON。
- “进入分镜”可直接打开项目中已保存的推理结果，不会再次调用模型；尚无分镜时会提示先进行推理。
- 每张分镜卡片提供视频预览占位区、可编辑/放大的视频提示词区域、角色/道具资产引用区和“生成视频”按钮；已保存视频 URL 时可直接预览。
- 分镜结果采用单列宽卡片布局，页面内容区扩展至工作区可用宽度，减少卡片右侧空白；底部状态栏固定显示，不再挤占创作区宽度。
- 视频生成已接入 AI 模型聚合平台 Muse Video（`muse-video`）：支持 4–30 秒、16:9/9:16、720p 文生视频及单张 HTTPS 图片参考；任务提交后自动轮询并保存状态和结果视频 URL。普通资产名称会附加到提示词上下文。
- Muse Video 费用由服务商按秒计费，本站不扣视频积分；提交任务前会显示时长并要求确认。生成失败的退款按服务商规则处理。为避免产生费用，开发验证不提交真实视频任务。
- 可单独编辑标题、画面描述、场景信息和模板扩展字段；“重新推理视频提示词”仅更新当前分镜提示词，“重新推理分镜”更新当前分镜内容。每次重新推理消耗 5 积分，成功后自动保存。
- 配置聊天模型后调用 OpenAI 兼容的 `chat/completions` 接口；模型拆解按次消耗 5 积分。
- 使用智谱 GLM-4.5 系列时，分镜请求显式关闭默认思考模式、启用 JSON 输出并预留 16,384 个输出 tokens，避免长 Skill 与剧本挤占最终结构化结果空间。
- 未配置聊天模型时不会退回本地拆句，会提示先配置聊天模型，避免未应用 Skill 的结果被误认为模型推理结果。

### SKILL 与提示词模板

- 提供内置创作 Skill，支持多选组合。
- 支持从侧边栏 SKILL 页面或剧本工具的“+上传Skill”入口上传 `.md`、`.txt`、`.skill` 文件。
- Skill 和个人提示词模板保存到账号；剧本拆解时将所选 Skill 内容与剧本一起填入模板。
- 模板支持 `{skill}` 和 `{script}` 两个变量。

### 账号、积分与模型配置

- 支持邮箱注册、登录和退出；注册密码长度为 10–128 个字符。
- 新账号获得 100 体验积分。
- 个人设置支持维护显示昵称、查看积分记录、配置聊天/图片/视频/音频模型。
- 模型 API Key 在服务端加密保存；浏览器只显示密钥提示信息，不返回完整密钥。
- 开发环境提供模拟充值；生产环境关闭模拟充值，正式支付尚未接入。

### 后端用量监控

- 服务端提供受令牌保护的用量快照和实时事件接口。
- 访问 `/admin` 使用墨序账号登录，可查看积分消耗、调用次数、活跃用户、模型配置数、使用趋势、账号用量和最近事件。
- 后台 API 要求有效登录会话及 `ADMIN_EMAILS` 邮箱白名单双重校验；只返回用量汇总，不提供积分修改、账号管理或密钥读取能力。
- 使用独立终端程序也可查看实时用量；终端监控接口继续使用独立的 `OBSERVABILITY_TOKEN`。

### 当前为占位或尚未接入的能力

- 图片生成和音频生成目前只有模型配置入口。
- 角色设定页面的部分编辑入口为占位交互。
- 正式支付、成片渲染和真实作品生成服务尚未接入。

## 技术架构与技术栈

| 层级 | 技术 | 用途 |
|---|---|---|
| 前端 | React 18、TypeScript | 单页创作应用与交互 |
| 前端构建与开发服务 | Vite 6、`@vitejs/plugin-react` | 开发服务器、API 代理、生产构建 |
| 图标 | lucide-react | 界面图标 |
| 后端 | Node.js、Express 5 | REST API、认证、项目和模型请求 |
| DOCX 解析 | Mammoth | 在浏览器端提取 DOCX 文本 |
| 开发辅助 | concurrently | 并行运行前端和后端开发进程 |
| 持久化 | JSON 文件 | 账号、积分交易、会话和用户项目 |

开发时 Vite 将 `/api` 请求代理到后端。生产环境中，前端静态资源和后端 API 应分别托管，并通过 `VITE_API_BASE_URL` 连接 API。

## 运行环境

- Node.js 24.21 或更高版本（当前启动脚本使用 Node 的 `--use-env-proxy` 参数）。
- npm。
- 使用大模型服务时，需要有效的模型服务商 API Base URL、模型名称和 API Key。
- 模型请求由后端通过 HTTPS 直连服务商；若使用 Fake-IP DNS，后端会先经公开 DNS 校验并固定公网 IP。运行环境需允许后端直连模型服务商。

## 本地启动

在项目根目录执行：

```bash
npm install
npm run dev
```

开发服务地址：

| 服务 | 本地地址 | 说明 |
|---|---|---|
| 前端 | http://localhost:5173 | Vite 开发服务器 |
| 后端 | http://localhost:3001 | Express API |
| 健康检查 | http://localhost:3001/api/health | 返回 `{"status":"ok"}` |

Vite 默认将 `/api` 转发到 `http://localhost:3001`。若后端运行在其他地址，可通过 `VITE_DEV_API_PROXY_TARGET` 指定开发代理目标。

也可以分别启动：

```bash
npm run dev:web
npm run dev:server
```

### 建议的手工验收流程

1. 在前端注册账号并登录，确认获得体验积分。
2. 打开“短剧工坊”，创建项目，输入剧本并确认项目自动保存。
3. 测试 `.txt`、`.md` 或 `.docx` 文档导入。
4. 在“SKILL”页面上传自定义 Skill，保存设置；回到剧本工具确认可在“+选择 Skill”中选中。
5. 在“个人设置 → 大模型 API”配置聊天模型，填写服务商提供的精确模型 ID，先保存，再使用“测试连接”；测试只读取可用模型列表，不会生成内容或产生推理费用。
6. 返回短剧工坊点击“推理分镜”，确认使用所选 Skill 生成结果、跳转到独立分镜结果页、项目保存并产生对应积分记录。
7. 打开“创作画布”，移动场景节点后刷新项目，确认修改仍存在。

模型拆解会产生 5 积分费用；进行端到端验收前请确认账号积分充足。连接测试不扣平台积分。

## 生产部署

生产部署需要分别配置前端和后端的公网地址。以下环境变量由运行环境注入；后端 Node 进程不会自动读取 `.env` 文件。Vite 会在构建时读取 `VITE_*` 变量。

### 前端构建变量

```env
VITE_API_BASE_URL=https://api.example.com
```

构建并将 `dist/` 发布到静态托管服务：

```bash
npm run build
```

### 后端变量

```env
NODE_ENV=production
PORT=3001
FRONTEND_ORIGINS=https://studio.example.com
MODEL_CONFIG_SECRET=<64位十六进制密钥>
OBSERVABILITY_TOKEN=<至少32位随机令牌>
```

生成随机密钥示例：

```bash
openssl rand -hex 32
```

使用生产环境变量启动后端：

```bash
npm start
```

### Render 与在线测试部署

GitHub 用于托管源代码，不能直接运行本项目的 Express 后端。GitHub Pages 只能托管静态前端；若要让用户注册、登录并保存项目，需要同时部署前端静态站点和 Node.js 后端，并为后端配置持久化存储。

仓库根目录的 `render.yaml` 已定义前后端服务：静态前端构建并发布 `dist/`，Express API 使用 `npm start`，并自动互相配置公网来源和 API URL。API 数据目录挂载到 `/var/data` 持久磁盘，SPA 路由会回退到 `index.html`。

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/Userdobe/moxu-studio-ST_Website)

1. 在 Render Dashboard 创建 Blueprint，选择本 GitHub 仓库并检查将创建的资源。
2. 按 Render 提示设置未同步的 `ADMIN_EMAILS`，填写允许访问只读管理后台的邮箱。
3. 确认 API 的付费实例和持久磁盘价格后再创建；持久磁盘不适用于免费 Web Service，服务与磁盘会产生费用。
4. 部署成功后，分别使用 Render 提供的前端和后端 URL 测试注册、登录、项目保存和后端 `/api/health`。测试通过后，将两个公网地址补充到“本地测试入口”。

当前邮箱注册 API 已开放，新账号默认获得 100 体验积分；生产环境模拟充值关闭，正式支付尚未接入。公开仓库本身不会产生在线服务地址，也不会自动创建或托管生产数据库。上线前应选择托管平台并确认其费用、持久化策略和备份方式。

注意事项：

- `FRONTEND_ORIGINS` 应填写前端完整来源（协议、域名和端口），多个来源用逗号分隔。
- 生产前后端跨站部署时，前端与后端均需使用 HTTPS，以支持安全会话 Cookie。
- `MODEL_CONFIG_SECRET` 应长期稳定并妥善备份；更换密钥会影响已保存模型 API Key 的解密。
- 如不设置 `DATA_DIRECTORY`，账号和项目数据写入项目下的 `data/` 目录。生产建议将该目录映射到持久化磁盘并限制文件访问权限。
- 后端可使用 `HTTP_PROXY` / `HTTPS_PROXY` 访问公开 DNS-over-HTTPS 服务；模型 API 请求使用校验后的公网 IP 直连，因此部署网络必须允许到模型服务商的出站 HTTPS。
- 不要将 `.env`、真实 API Key、监控令牌或 `data/` 数据提交到代码仓库。

## 主要 API

所有账号和项目接口都需要已登录会话。完整路由以 `server/index.js` 为准。

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/health` | 后端健康检查 |
| `POST` | `/api/auth/register` | 注册账号 |
| `POST` | `/api/auth/login` | 登录 |
| `POST` | `/api/auth/logout` | 退出登录 |
| `GET` | `/api/auth/me` | 获取当前账号 |
| `GET` | `/api/admin/me` | 校验后台管理员权限（需要管理员登录） |
| `GET` | `/api/admin/usage?window=24h` | 读取网页后台用量快照（需要管理员登录） |
| `GET` / `PUT` | `/api/account/skills` | 读取或保存 Skill 和提示词设置 |
| `PUT` | `/api/account/model` | 保存或移除模型配置 |
| `POST` | `/api/account/model/test` | 测试模型连接；聊天模型执行轻量生成请求 |
| `POST` | `/api/tools/breakdown` | 使用聊天模型拆解剧本 |
| `GET` / `POST` | `/api/projects` | 列出或创建项目 |
| `GET` / `PUT` / `DELETE` | `/api/projects/:id` | 读取、更新或删除项目 |
| `GET` | `/internal/observability/usage` | 读取用量快照（需要监控令牌） |
| `GET` | `/internal/observability/usage/events` | 订阅用量事件 SSE（需要监控令牌） |

运行后端终端监控：

```bash
npm run monitor
```

启动监控前，应在当前终端配置与后端相同的 `OBSERVABILITY_TOKEN`。可通过 `OBSERVABILITY_URL` 指定远程后端、`OBSERVABILITY_WINDOW` 选择 `1h`、`24h`、`7d` 或 `30d` 时间窗。

## 数据与安全

- 默认数据位置：`data/accounts.json`、`data/projects/<用户ID>/` 和 `data/.model-config-key`。
- 密码以带随机盐的 scrypt 哈希保存，不以明文存储。
- 登录会话通过 HttpOnly Cookie 传递；服务端持久化会话令牌哈希。
- 模型 API Key 使用 AES-256-GCM 加密后保存。
- 模型请求禁止重定向，并检查目标域名解析结果，阻止访问本机和内网地址。
- 代理网络使用公开 DNS 查询绕过 Fake-IP 解析；模型 API 连接固定到校验过的公网 IP，并保留 TLS 主机名校验。所有解析结果仍会检查并拒绝本机或内网地址。
- 用量监控路由不暴露在普通前端页面中，并使用单独配置的监控令牌进行身份校验。
- 网页后台 API 需要有效的 HttpOnly 登录会话，并且账号邮箱必须列入服务器端 `ADMIN_EMAILS`；不要将管理员密码写入环境文件或代码。
- 开发时可在被忽略的 `.env` 中设置 `ADMIN_EMAILS=admin@example.com`；生产环境应通过部署平台的服务器端环境变量配置管理员邮箱。

## 当前限制

- 用户、积分流水、会话和项目当前以 JSON 文件持久化；多实例部署需要改用共享数据库或集中式存储。
- 图片、视频、音频模型配置已提供，但相应生成工具仍需单独接入。
- 当前支付为开发模拟模式，不应作为真实支付能力使用。
- 是否能成功调用模型取决于服务商 API 地址、模型权限、账户余额、服务状态及后端的直连网络。
